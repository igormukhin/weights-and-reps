# Implementation Plan: E2E Test Automation Setup

**Branch**: `005-e2e-test-setup` | **Date**: 2026-04-08 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/005-e2e-test-setup/spec.md`

## Summary

Set up Playwright E2E testing against the Firebase Emulator Suite so that a CI pipeline automatically validates that a logged-in user can add an exercise and see it persist. Auth uses email/password via the Firebase Auth Emulator (bypassing Google OAuth). Firestore uses `memoryLocalCache` in test mode to avoid IndexedDB issues in headless Chromium. Tests run against a production build served by `vite preview`. Emulator state is reset once per suite run via the emulator REST API.

**Language/Version**: TypeScript 5.6 (strict mode)

## Implementation Phases

### Phase A: Firebase Emulator Configuration

1. **Update `firebase.json`** — add `emulators` block with Auth (9099), Firestore (8080), and UI (4000) ports.

2. **Update `src/services/firebase.ts`** — add emulator detection:
   - When `import.meta.env.VITE_USE_FIREBASE_EMULATOR === 'true'`: use `memoryLocalCache()`, call `connectFirestoreEmulator(db, 'localhost', 8080)` and `connectAuthEmulator(auth, 'http://localhost:9099')`.
   - Production path unchanged.

3. **Create `.env.test.example`** — committed file with all `VITE_FIREBASE_*` set to demo values and `VITE_USE_FIREBASE_EMULATOR=true`.

4. **Add `.env.test` to `.gitignore`**.

### Phase B: Playwright Installation & Configuration

5. **Install Playwright** — `npm install -D @playwright/test` and `npx playwright install chromium`.

6. **Create `playwright.config.ts`** at project root:
   - `baseURL`: `http://localhost:4173`
   - `webServer`: `command: 'npm run build:test && vite preview'`, `url: 'http://localhost:4173'`, `reuseExistingServer: !process.env.CI`
   - `globalSetup`: `'./e2e/global-setup.ts'`
   - Single project: Chromium
   - Reporter: `html` (CI) + `list` (local)

7. **Add npm scripts to `package.json`**:
   - `"build:test": "vue-tsc -b && vite build --mode test"`
   - `"test:e2e": "playwright test"`

### Phase C: Global Setup & Auth Fixture

8. **Create `e2e/global-setup.ts`**:
   - Reset Firestore: `DELETE http://localhost:8080/emulator/v1/projects/demo-test/databases/(default)/documents`
   - Reset Auth: `DELETE http://localhost:9099/emulator/v1/projects/demo-test/accounts`
   - Create test user: `POST http://localhost:9099/identitytoolkit.googleapis.com/v1/accounts:signUp?key=fake-api-key`
   - Throw with a clear error if any request returns non-200.

9. **Create `e2e/fixtures/auth.ts`**:
   - Export `TEST_USER = { email: 'test@example.com', password: 'testpassword123' }`
   - Export `signInAsTestUser(page)` — calls `page.evaluate()` to invoke `signInWithEmailAndPassword` from the Firebase SDK in the browser context, then waits for the auth state to resolve.

### Phase D: Add Exercise Test

10. **Create `e2e/exercises/add-exercise.spec.ts`**:
    - `beforeEach`: call `signInAsTestUser(page)`, navigate to `/exercises`.
    - **Test 1 — "add exercise appears in list"**:
      - Click the add exercise button.
      - Type `Bench Press` into the exercise name input.
      - Submit.
      - Assert `Bench Press` is visible in the exercise list.
    - **Test 2 — "add exercise persists after reload"**:
      - (Continues from Test 1 state, since suite-level reset only.)
      - Reload the page.
      - Assert `Bench Press` is still visible.

    Use Playwright's `data-testid` attributes for selectors where possible. If the existing components don't have `data-testid` attributes, use stable text-based selectors (role + name).

### Phase E: CI Workflow

11. **Create `.github/workflows/e2e.yml`**:
    - Trigger: `push` and `pull_request` on all branches.
    - Steps: checkout → Node.js 20 setup → `npm ci` → `npx playwright install --with-deps chromium` → copy `.env.test.example` to `.env.test` → `npx firebase emulators:exec --only auth,firestore "npm run test:e2e"`.
    - Upload `playwright-report/` as artifact on failure.

## Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Auth in tests | Email/password via emulator, `page.evaluate()` | Google OAuth popup can't be automated |
| Firestore cache | `memoryLocalCache()` in test mode | IndexedDB unreliable in headless Chromium |
| App serving | `vite preview` via Playwright `webServer` | No extra packages; already available |
| Emulator reset | HTTP DELETE to emulator REST API | No Admin SDK needed; built into emulator |
| CI emulator lifecycle | `firebase emulators:exec` | Clean start/stop wrapping the test command |
| Project ID | `demo-test` | `demo-` prefix blocks all real Firebase network calls |
| Test selectors | `data-testid` preferred; text-based fallback | Resilient to Vuetify DOM structure changes |

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| `page.evaluate()` sign-in depends on Firebase SDK being available in window scope | Import Firebase auth in the evaluate callback using the module already bundled in the app |
| Vite build step in CI adds ~60s per run | Acceptable for MVP; consider caching `dist/` by `src/` hash in future |
| Emulator ports conflict with other local services | Ports 8080/9099 are standard; documented in quickstart |
| Firestore security rules not applied in emulator by default | `firebase.json` must reference `firestore.rules` so emulator loads them |
